🎬 Demo Runbook — AI Essay & Quiz Grader

กลุ่ม Dario Amodei · นำเสนอ Sec วันพุธ · เตรียมก่อนนำเสนอ 15 นาที

สรุปสิ่งที่ต้องทำวันนำเสนอ (3 ขั้นตอน):
  1. เปิด Terminal → cd ~/Projects/ai-essay-grader → python3 serve.py (ห้ามปิดหน้าต่างนี้)
  2. เปิดเบราว์เซอร์ → http://localhost:8000 → มุมขวาบนต้องขึ้นป้ายเขียว "LIVE · AI ทำงานจริง"
  3. ทำตามคิวการสาธิตด้านล่าง — ทุกอย่างมีปุ่มสำเร็จรูป ไม่ต้องพิมพ์เองเลย
⛔ ห้ามทำ / ข้อควรระวัง:
  • ห้าม demo จากลิงก์ GitHub Pages — เวอร์ชันนั้นเป็น Demo Mode (ไม่มี proxy) ป้ายจะขึ้นสีเหลือง "DEMO" ถ้าขึ้นแบบนั้นแสดงว่าเปิดผิด URL
  • ห้ามปิด Terminal ที่รัน serve.py ระหว่างนำเสนอ — ปิดเมื่อไหร่ แอปตายทันที
  • ห้ามแชร์/โพสต์ไฟล์ key.txt หรือแคปหน้าจอที่เห็นเนื้อหาไฟล์นี้
  • ถ้าอินเทอร์เน็ตห้องเรียนล่ม → แอปจะ error ชัดเจน ไม่ต้องโกหกว่า live: สลับไปเล่า Demo Mode ได้ (ป้ายเหลือง) หรือเปิดวิดีโอ/สกรีนช็อตสำรอง
  • AI ตอบไม่เหมือนกันทุกรอบ — คะแนนอาจต่างจากในเอกสารนี้ เป็นเรื่องปกติ และเป็นจุดขาย (พูดตามสคริปต์ข้อ 4)

📋 คิวการสาธิต (ประมาณ 5–7 นาที)

#ทำอะไร (กดอะไร)สิ่งที่คนดูจะเห็น + สคริปต์พูด
1 แท็บ ตรวจเรียงความ → กดปุ่ม 🇹🇭 เรียงความไทย (คุณภาพดี) → กด ✨ ตรวจและให้คะแนน รอ ~15–40 วินาที (มี spinner) → คะแนนรวม + รายเกณฑ์ 4 ด้าน ทุกเกณฑ์มีคอมเมนต์ภาษาไทย และ กล่อง "หลักฐานจากตัวงาน (Anti-Hallucination)" ที่ quote ข้อความจริงจากเรียงความ
"สังเกตว่าทุกคะแนน AI ต้องยกข้อความจริงจากงานนักเรียนมาเป็นหลักฐาน — นี่คือกลไกกัน AI มโนที่เราฝังไว้ในระบบ"
2 เปิด 🔍 Transparency — ดูคำสั่ง (prompt) ที่จะส่งให้ AI เห็น prompt จริงทั้งก้อน รวมถึงกฎ anti-bias ที่เขียนกำกับ AI ไว้
"ผู้ใช้ดูได้ว่า AI ถูกสั่งอะไร และตัดสินจากเกณฑ์ไหน — ไม่มี black box"
3 กด 🇬🇧 English essay (strong) → ตรวจ → จดคะแนน → แล้วกด 🌏 non-native writer — bias test → ตรวจอีกครั้ง ไฮไลต์ของงาน! ผลทดสอบจริงที่เราวัดได้: strong ได้ 36/40 vs non-native ได้ 26/40 ทั้งที่เนื้อหาและเหตุผลลึกพอ ๆ กัน ต่างแค่ความลื่นไหลของภาษา
"สองงานนี้เราจงใจเขียนให้เนื้อหาดีเท่ากัน แต่ชิ้นหนึ่งเขียนโดยจำลองสไตล์ non-native — ผลต่าง 10 คะแนนเต็มคือหลักฐานว่า Bias & Fairness ไม่ใช่ทฤษฎีลอย ๆ แต่เกิดขึ้นจริงกับระบบแบบนี้ และนี่คือเหตุผลที่ต้องมีมนุษย์ทบทวนคะแนนเสมอ"
4 กด 🔁 Consistency Check (×3) ระบบตรวจงานเดิม 3 รอบ → ตารางเทียบคะแนนรายเกณฑ์รายรอบ พร้อมส่วนต่าง (รอบทดสอบจริงเราได้ 34→34→30 = แกว่ง 4 คะแนน)
"งานเดิม คนเดิม ตรวจ 3 ครั้ง คะแนนไม่เท่ากัน — นี่คือปัญหา Reliability ที่ผู้ใช้อาจไม่รู้ตัว ถ้าเราไม่โชว์ให้ดูตรง ๆ"
5 ตรงช่อง สิทธิ์ครู (Human Oversight) → แก้คะแนน → ใส่เหตุผล → กด ✍️ บันทึก → เปิดแท็บ Audit Log เห็นบันทึก: เวลา · คะแนน AI → คะแนนที่มนุษย์แก้ · เหตุผล (ถ้าไม่ใส่เหตุผล ระบบไม่ยอมให้บันทึก — ลองให้ดูได้)
"ครูแก้คะแนนได้เสมอ แต่ต้องรับผิดชอบเป็นลายลักษณ์อักษร — AI เป็นผู้ช่วย ไม่ใช่ผู้ตัดสิน"
6 แท็บ ตรวจข้อสอบปรนัย → กด 📄 ชุดที่ 2 (จริยธรรม AI) → กด ✨ สร้างเฉลยและตรวจคำตอบ AI สร้างเฉลย 4 ข้อพร้อมคำอธิบายรายข้อ → เทียบคำตอบนักเรียน (ชุดนี้จงใจตอบผิด 1 ข้อ) → เห็น ✓/✗ รายข้อ + คะแนน 3/4
"โจทย์ชุดนี้คือข้อสอบจริยธรรม AI เอง — ให้ AI เฉลยข้อสอบที่ถามเรื่องจริยธรรมของมันเอง เป็นการปิดท้ายที่ชวนคิดดีครับ/ค่ะ"
7 กด 🔒 ความเป็นส่วนตัว (มุมขวาบน) แสดงนโยบาย: ไม่เก็บงานนักเรียน · key อยู่ฝั่ง proxy ไม่ผ่านเบราว์เซอร์ · audit log อยู่ในเครื่อง
"Privacy by design — และเราระบุข้อจำกัดตรง ๆ ว่าถ้าส่งงานไป API ภายนอก ข้อมูลยังอยู่ใต้นโยบายผู้ให้บริการ โรงเรียนที่ต้องการเข้มงวดควรใช้ on-premise model"
💡 ถ้าเวลาเหลือ: กด 💼 Pitch Deck เพื่อโชว์ว่าสลับ rubric ได้ (ตรวจข้อเสนอธุรกิจ EduFair) · หรือกด 🇹🇭 ควรปรับปรุง เพื่อโชว์ว่างานคุณภาพต่ำได้คะแนนต่ำจริง (ระบบไม่ได้ใจดีกับทุกงาน)

🆘 แผนสำรองเมื่อมีปัญหา (Troubleshooting)

อาการสาเหตุ + วิธีแก้
ป้ายมุมขวาขึ้น "DEMO MODE" ทั้งที่เปิด localhostserve.py ไม่ได้รัน หรือรันโดยไม่เห็น key → เปิด Terminal ใหม่: cd ~/Projects/ai-essay-grader && python3 serve.py แล้วรีเฟรชหน้าเว็บ — ป้ายต้องเปลี่ยนเป็นเขียว LIVE (Demo Mode ก็ยังนำเสนอได้ แต่ต้องบอกตรง ๆ ว่าเป็นผลจำลอง)
กดตรวจแล้วขึ้น ❌ errorส่วนใหญ่คือเน็ตหลุด/ช้า หรือ API ตอบว่าง → กดปุ่มตรวจซ้ำได้เลย (ระบบมี auto-retry 1 ครั้งอยู่แล้ว) ถ้ายังไม่หาย รอ 10 วิแล้วลองใหม่
รอนานผิดปกติ (> 1 นาที)โมเดลเป็น reasoning model ใช้เวลา "คิด" ก่อนตอบ → ระหว่างรอให้พูดอธิบาย spinner / เปิด Transparency panel ฆ่าเวลา — ไม่ต้องนิ่งเงียบ
Port 8000 ถูกใช้PORT=8080 python3 serve.py แล้วเปิด http://localhost:8080
อินเทอร์เน็ตห้องใช้ไม่ได้เลยเปิดสกรีนช็อต/คลิปที่เตรียมไว้ หรือสลับไป Demo Mode แล้วพูดตรง ๆ ว่า "โหมดจำลองมีไว้สำหรับสถานการณ์แบบนี้ — สังเกตว่าแอปติดป้าย DEMO ชัดเจน ไม่หลอกผู้ใช้ว่าผลเป็น AI จริง" (เปลี่ยนจุดอ่อนเป็นตัวอย่างความโปร่งใสได้!)

🎤 คำถามที่อาจารย์อาจถาม + แนวคำตอบ

  • "คะแนนเชื่อถือได้แค่ไหน?" → ตอบตรง ๆ: ไม่น่าเชื่อถือพอให้ตัดสินมนุษย์เดี่ยว ๆ — นั่นคือเหตุผลที่เราทำ Consistency Check ให้เห็นกับตา และบังคับ Teacher Override พร้อม audit log
  • "ใครรับผิดชอบถ้า AI ให้คะแนนผิด?" → ตามดีไซน์ของเรา: ครูผู้ยืนยันผลเป็นคนรับผิดชอบ (human-in-the-loop) โดยมี audit trail ย้อนดูได้ — และเรายอมรับว่าในกฎหมายปัจจุบันยังไม่มีคำตอบระดับอุตสาหกรรมที่ชัด
  • "ข้อมูลนักเรียนไปไหน?" → ไม่ถูกเก็บฝั่งเรา (stateless) แต่ถูกส่งไปผู้ให้บริการโมเดลตาม prompt ที่แสดงโปร่งใสใน Transparency panel — ถ้าเป็นข้อมูลอ่อนไหวของเยาวชนจริง ควร anonymize ก่อน หรือใช้ on-premise model
  • "vibe coding ทั้งโปรเจกต์แบบนี้ นักศึกษาได้อะไร?" → เราไม่ได้เขียนโค้ดเอง แต่เรากำกับ ตรวจสอบ และรับผิดชอบ: กำหนดสถาปัตยกรรม, เทียบผล AI กับ expectation, เจอบั๊กจริง (reasoning model ตอบว่าง) และตัดสินใจเชิงจริยธรรมทุกอย่างที่ฝังในแอป — สไลด์หน้า 6 เล่าตรง ๆ ว่าความเสี่ยงคืออะไร

ผลทดสอบจริงทั้งหมดในเอกสารนี้ (36 vs 26 คะแนน bias test, 34→34→30 consistency) มาจากการรันแอปกับ Qwen 3.8 Max จริงเมื่อวันที่ 27 ต.ค. 2569 — คะแนนวันนำเสนอจริงอาจต่างไปเล็กน้อย ซึ่งคาดได้และอธิบายได้
